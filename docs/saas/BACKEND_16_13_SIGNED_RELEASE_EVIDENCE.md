# Backend16.13 — independently signed, offline staging release evidence

**Status: unmounted source-only security gate; not a production
authorization, Railway deployment, migration or replacement for human review.**

## What this closes and what it does NOT

The project previously tracked backend readiness in prose, with successful
GitHub CI but no executable check distinguishing CI-only SQL0008 experiments
from the permanent staging migration. This increment adds a fail-closed
**offline release evidence verifier**:
`src/features/saasBlueprint/controlApi/server/backend16ReleaseEvidenceGate.ts`.

It verifies **ten** named conditions covering permanent SQL0008 installed
readback, staging restore drill, actual CA+hostname `verify-full`, versioned
per-LOGIN vault/IAM, live OIDC session revocation, durable off-host audit
replay, two-tenant private E2E, canary rollback, independent security review,
and independent operations review. Every gate has a bounded freshness window,
exact Railway staging IDs, an exact 40-hex Git source commit, a narrowly
allowlisted proof location, a SHA256 of the independently archived redacted
proof, a role-bound signer and an Ed25519 signature.

The verifier never contacts Railway, PostgreSQL, an identity provider,
a vault or the network. It does not create/pin keys, provision credentials,
produce a signed approval, apply SQL, or deploy Core/Gateway. It has no default
approved signer keys. Its result `READY_FOR_INDEPENDENT_REVIEW` always has
`productionAuthorized:false`: the result is **not** a command to ship.

## Attestation signers and independent trust

A *separate reviewed operator policy*, outside HTTP requests, CI fixtures,
PostgreSQL catalog values and the evidence archive itself, must pin:

- The exact audited release `sourceCommitSha`, **not** a moving `main`.
- One role-ordered **public-only** Ed25519 verification key per
  `db-operator`, `security-reviewer`, `runtime-reviewer`, and
  `operations-reviewer`, each with a distinct signer ID and public key.
- SHA256 of `backend16CanonicalOperatorKeyset(keys)`, independently
  approved, not recomputed at startup from an untrusted keyset.

No Ed25519 signing/private keys are shipped, generated by production
code, stored in GitHub, copied to Railway, or entrusted to the runtime.
The private keys belong to independently identified operator signing
infrastructure with controlled lifecycle and revocation. Key rotation
requires a separately reviewed new public-key manifest and all new
signatures, never reusing old approvals. Signature verification uses
WebCrypto Ed25519, not a mutable header or shared HMAC secret.

Only records of schema `backend16-release-evidence-v1` are valid. The
canonical signature preimage is exactly
`backend16CanonicalReleaseEvidence(evidence)`; the function builds an
explicitly ordered JSON object so property insertion order from input does
not change signed bytes. External records must contain exactly the known
properties, be plain records with no getters or extra keys, use the
approved role and signer ID and have a valid Ed25519 signature over
all properties.
The verifier also makes a **synchronous immutable snapshot** of the
operator keyset and all evidence records before invoking any asynchronous
WebCrypto call or test clock callback. Mutating a supplied JavaScript
object while signatures are checked cannot change the reviewed subject.
Concurrent key/proof replacement is covered by a regression test.

## Evidence sequence and expiry

| Condition | Required signer | Max age |
| --- | --- | --- |
| SQL0008 **installed-mode** independent readback | DB operator | 1 hour |
| Actual isolated staging restore drill | Operations reviewer | 24 hours |
| CA-chain + DNS SAN `verify-full` | Security reviewer | 1 hour |
| Real per-LOGIN vault/IAM/version/revocation | Security reviewer | 1 hour |
| Live OIDC + session revoke E2E | Security reviewer | 1 hour |
| Durable off-host redacted audit replay/ACK | Security reviewer | 1 hour |
| Two-tenant private HTTP E2E | Runtime reviewer | 1 hour |
| Staging canary rollback and fail-close | Runtime reviewer | 30 minutes |
| Independent security release review | Security reviewer | 30 minutes |
| Independent operations release review | Operations reviewer | 30 minutes |

Each evidence record must be observed in the past, not expired at review
time, and not older than its limit. An invalid or missing gate results in
`BLOCKED`, never permissive partial approval. Both final review records
must be signed **after all eight technical observations**. Their signed
`proofSha256` is the SHA256 of the complete, ordered **v2 aggregate of
all eight independently verified signed technical attestations**:

```ts
const canonical = backend16CanonicalSignedTechnicalBundle(
  technicalGates.map(gate => signedEvidence[gate]),
);
// Exact canonical JSON preimage:
JSON.stringify({
  schema: 'backend16-technical-signed-release-evidence-v2',
  gates: technicalGates.map(gate => [
    gate,
    backend16CanonicalReleaseEvidence(signedEvidence[gate].evidence),
    signedEvidence[gate].signatureHex,
  ]),
});
const approvalProofSha256 = sha256(canonical); // example only; no signer key
```

The v1 digest-of-proof-hashes form is **obsolete and rejected**. Because two
distinct valid signed observations can reference the same archived
`proofSha256` while differing in observation time, URI, validity or
signer signature, a proof-hash-only aggregate did *not* bind the exact
reviewed records. Changing *any* technical signed record requires new
security and operations review signatures, even when the raw proof digest
stays identical. Never compute a purported approval from unverifiable data
or silently migrate/reuse existing approval signatures. This code verifies
only; all approvals require separately authorized human signers.

Evidence URLs are limited to this GitHub repository's Actions runs,
pull requests or issues and the exact Railway staging project/service
URLs. The checker does **not** retrieve the URL or independently verify
that the archive file's bytes match its digest — that must be performed
by an independent approved archive verifier before signature issuance.
A valid signature is an operator statement, not a mathematical proof
that the real world is safe. Never sign missing or invented evidence.
