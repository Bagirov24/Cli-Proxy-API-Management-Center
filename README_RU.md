## Единый интерфейс управления

Основные операции — от настройки сервера до диагностики — доступны в веб-интерфейсе.

| Конфигурация | Подключения | Мониторинг |
| --- | --- | --- |
| Редактирование параметров через формы или YAML с просмотром различий перед сохранением | Управление ключами провайдеров, файлами авторизации и OAuth | Проверка состояния сервера, квот и журналов запросов |

**Сборка в один HTML-файл** · **Адаптивный интерфейс** · **Поддержка нескольких языков**

> [!IMPORTANT]
> Требуется **CLI Proxy API версии 8.0.0 или новее**; рекомендуется актуальная версия v8. Этот репозиторий содержит **интерфейс управления, а не сам прокси**: приложение не перенаправляет API-трафик. Оно использует **Management API v8** (`/v8/management`) и соответствующую структуру конфигурации, без резервного переключения на v0. Пути ресурсов плагинов и пользовательских расширений сохраняются такими, какими их объявляет backend.

## Быстрый старт

В обычной установке интерфейс уже включён в [CLI Proxy API](https://github.com/router-for-me/CLIProxyAPI): отдельный frontend развертывать не нужно.

1. Запустите CLI Proxy API.
2. Откройте `http://<host>:<api_port>/management.html`.
3. Введите **ключ управления** (management key) и подключитесь.

Адрес API определяется по URL страницы; при необходимости его можно задать вручную.

> [!NOTE]
> **Ключ управления** служит для входа в эту панель. Клиентские ключи из `access.api-keys` разрешают обращения к самому прокси. Это **разные ключи**, их нельзя подменять друг другом.

<details>
<summary><strong>Настройки подключения и удалённый доступ</strong></summary>

Интерфейс принимает адреса вида `localhost:8317`, `https://example.com:8317` и `http://example.com:8317/v8/management`. Суффикс Management API автоматически удаляется из введённого адреса.

Для запросов к панели используется `Authorization: Bearer <MANAGEMENT_KEY>`. Удалённое управление в некоторых конфигурациях требует `management.allow-remote: true` на стороне сервера; прежде чем включать его, оцените риски публичного доступа. Подробности — в [документации backend](https://github.com/router-for-me/CLIProxyAPI).

</details>

<details>
<summary><strong>Переход с версии v7</strong></summary>

Сначала обновите backend и сделайте резервную копию `config.yaml`. При чтении backend возвращает структуру конфигурации v8; успешная запись через интерфейс v8 переводит сохранённый файл на новый формат.

- `access.api-keys` — клиентские ключи доступа к прокси.
- `api-keys` на верхнем уровне — группы ключей вышестоящих провайдеров.

</details>

### Если используется отдельный публичный Caddy Gateway

**Не путайте эту панель управления с публичным API Gateway.** Публичный Gateway в нашей схеме пропускает только разрешённые клиентские API-маршруты и намеренно не открывает `/management.html` и административные API. Управляйте Core через защищённый приватный доступ, например SSH-туннель.

Описание архитектуры Gateway, CPA-авторизации, лимитов по IP и отката находится в [русской инструкции Gateway (ветка api-gateway)](https://github.com/Bagirov24/Cli-Proxy-API-Management-Center/blob/api-gateway/integrations/api-gateway/README.md).

## Возможности

| Раздел | Что можно делать |
| --- | --- |
| **Панель состояния** | Смотреть статус подключения, версию сервера, дату сборки и доступность моделей |
| **Конфигурация** | Изменять основные настройки и клиентские ключи; работать с YAML, поиском, подсветкой и предварительным просмотром изменений |
| **AI-провайдеры** | Настраивать Gemini, Codex, Claude, Vertex и OpenAI-совместимые API, ключи, заголовки, прокси и сопоставление моделей |
| **Файлы авторизации и OAuth** | Загружать, скачивать и упорядочивать учётные данные, подключать поддерживаемые провайдеры через OAuth или device flow, задавать алиасы и исключения моделей |
| **Квоты** | Просматривать данные об использовании и лимитах у поддерживаемых провайдеров, включая Claude, Antigravity, Codex, Kimi и xAI/Grok |
| **Журналы** | Просматривать логи с автообновлением и поиском, скрывать служебный трафик, скачивать журналы ошибок запросов |
| **Плагины** | Управлять плагинами, если подключённый backend сообщает о поддержке |
| **Система** | Проверять обновления, просматривать модели и очищать локальные данные входа |

Интерфейс поддерживает выбор языка, в том числе **русский**, определяет язык браузера и адаптируется к компьютерам, планшетам и телефонам в современных версиях Chrome, Firefox, Safari и Edge.

## Сборка и развёртывание

Для самостоятельной сборки одностраничного интерфейса используйте **Bun 1.3.14**:

```bash
bun install --frozen-lockfile
bun run build
```

Результат — **`dist/index.html`** с JavaScript, CSS и ресурсами внутри одного HTML-файла. Во время публикации релиза файл переименовывается в `management.html` для размещения на backend.

Локальный просмотр: `bun run preview`. Лучше использовать HTTP-сервер: при открытии страницы напрямую через `file://` возможны ограничения CORS.

<details>
<summary><strong>Сведения о релизах</strong></summary>

- Git-теги формата `vX.Y.Z` запускают [workflow выпуска](.github/workflows/release.yml).
- Версия интерфейса во время сборки выбирается последовательно из `VERSION`, git-тегов, версии пакета; запасное значение — `dev`.
- Hash-маршрутизация и целевая платформа ES2020 упрощают размещение.

</details>

## Разработка

```bash
bun install --frozen-lockfile
bun run dev
```

Затем откройте `http://localhost:5173` и подключите backend.

**Технологии:** React 19 · TypeScript 6 · Vite 8 · Zustand · Axios · React Router 7 · Motion · CodeMirror 6 · SCSS Modules · i18next.

| Команда | Назначение |
| --- | --- |
| `bun run dev` | Запуск Vite в режиме разработки |
| `bun run build` | Проверка TypeScript и production-сборка |
| `bun run preview` | Локальный просмотр сборки |
| `bun run test` | Запуск тестов Bun |
| `bun run lint` | Проверка ESLint (предупреждения не приводят к ошибке) |
| `bun run type-check` | Проверка `tsc --noEmit` |
| `bun run verify` | Тесты, lint и сборка |
| `bun run format` | Форматирование исходников через Prettier |

Сообщения об ошибках и pull request приветствуются. Для изменений интерфейса приложите шаги воспроизведения, версии backend и UI, скриншоты и результаты проверки. Правила проекта — в [AGENTS.md](AGENTS.md).

## Безопасность

**Ключ управления — секрет.** Если включена опция «Запомнить пароль», ключ сохраняется в хранилище браузера с обратимым сокрытием символов. **Это не шифрование и не защита от компрометации браузера.**

Используйте доверенное устройство или отдельный профиль браузера. Включайте удалённое управление только после оценки рисков доступа к серверу. Не публикуйте management key, OAuth-токены или CPA-ключи в репозитории, логах или обращениях за поддержкой.

## Решение проблем

<details>
<summary><strong>Не удаётся подключиться или пройти авторизацию</strong></summary>

- **Нет подключения / ошибка 401:** проверьте адрес API и ключ управления. Для удалённого подключения серверу может потребоваться отдельное разрешение на управление извне.
- **Повторяющиеся ошибки авторизации:** backend может временно блокировать внешние IP-адреса.

</details>

<details>
<summary><strong>Отсутствуют страницы, функции или не проходят тесты</strong></summary>

- **Нет страницы журналов:** включите настройку «Logging to file» в базовой конфигурации.
- **Функция недоступна:** проверьте версию backend и поддержку соответствующего маршрута. Часть возможностей зависит от версии Core.
- **Нет списка моделей:** для `/v1/models` требуется хотя бы один действующий клиентский API-ключ; отдельная политика может дополнительно запретить список моделей.
- **Не проходит тест OpenAI-провайдера:** тест выполняется в браузере и зависит от доступности провайдера и CORS. Сбой этого теста не обязательно означает, что backend не может обратиться к провайдеру.

</details>
